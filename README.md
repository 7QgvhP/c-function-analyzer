# C Function Analyzer

C言語の関数にカーソルを置いて実行すると、その関数の入出力変数・内部変数・呼び出し関数の一覧を Webview 画面で可視化する VS Code 拡張機能です。

正規表現ではなく [tree-sitter](https://tree-sitter.github.io/tree-sitter/) による構文解析（AST）を用いているため、多重ポインタ・多次元配列・構造体メンバ・関数ポインタといった記述も正しく判別します。

## 使い方

1. C言語ソースコード（`.c` や `.h`）を開きます。
2. 解析したい関数の **関数名がある行（シグネチャ行）** にカーソルを置きます。
3. ショートカットキー **`Ctrl + Alt + A`** を押すか、右クリックして **「関数を解析 (Analyze C Function)」** を選択します。
4. エディタが分割され、右側に解析結果が表示されます。

> カーソルは関数の**シグネチャ行**（戻り値の型の行から引数リストの閉じ括弧の行まで）に置いてください。関数ボディの中で実行した場合は解析されません。

実行中は画面右下に「関数を解析しています…」と表示され、終わると自動的に消えます。インクルードを多く辿るプロジェクトでは処理に時間がかかるため、進行中かどうかがここで分かります。

## 解析される内容

| 分類 | 内容 |
|---|---|
| **入力変数** | 値渡し引数、読み取りが行われているポインタ引数、読み取られているグローバル変数 |
| **出力変数** | 戻り値、書き込みが行われているポインタ引数、書き込まれているグローバル変数 |
| **内部変数** | 関数内で宣言されたローカル変数 |
| **呼び出し関数** | 関数内で直接呼び出されている関数（関数ポインタ経由の呼び出しは除外）。型名欄には**戻り値の型**を表示します |
| **マクロ変数 / マクロ関数** | `#define` で定義されている識別子、および `enum` の列挙子（定義が特定できない場合は大文字のみの名前から推定） |

読み取りと書き込みの両方が行われている変数（`+=`、`++`、`*p = *p + 1` など）は、**入力と出力の両方**に表示されます。

## 主な機能

### 定義位置の解決

型名・コメント・定義値・ジャンプ先は、いずれも**定義位置から読み取ります**。定義位置の特定には **VS Code の定義プロバイダ（F12 と同じもの）** を使います。

```
1. 現在のファイルを解析        参照位置を集める
2. 参照位置で F12 相当を呼ぶ   実際のビルド構成に基づく定義位置を得る
3. 定義位置の宣言を読む        型名・コメント・定義値を取り出す
```

構造体・共用体のメンバは、メンバ名の位置から定義を辿るため**メンバの宣言に直接到達**します。`g_cfg.mode` なら `mode` の宣言です。

各項目にマウスを乗せると表示される **「定義へ」ボタン**で、その場所へ移動できます。定義位置を特定できない項目（型名が `(推定)` の項目、標準ライブラリ関数、`戻り値 (return)` など）にはボタンを表示しません。

> **C/C++ 拡張（IntelliSense）が必要です。** 定義プロバイダが応答しない環境では、型名が `(推定)` のままになり「定義へ」ボタンも表示されません。F12 が使えていれば条件を満たしています。

### 呼び出し関数の表示

呼び出し関数の型名欄には**戻り値の型**が表示されます。

| 型名 | 名前 | 備考 |
|---|---|---|
| `S16` | `hal_read_raw` | 通常の戻り値 |
| `void` | `app_log` | `void` も明示します |
| `char*` | `get_buffer` | ポインタ戻り値 |
| `unsigned char` | `read_byte` | 型そのものの表記はそのまま |
| `(推定)` | `printf` | 宣言が見つからず型を特定できない場合 |

型名欄には**型だけ**が表示されます。記憶域クラス（`static` `extern` `inline`）と型修飾子（`const` `volatile`）は含みません。変数の型名欄と同じ扱いです。

```c
static void        s_fn(void);   /* 型名欄は void */
const char        *c_fn(void);   /* 型名欄は char* */
static const char *sc_fn(void);  /* 型名欄は char* */
```

マクロ関数は型名欄が `macro` となり、定義値欄に展開内容が表示されます。

### マクロ変数の表示

マクロ変数は「型名 → 定義名 → **定義値**」の3列で表示されます。`#define` と `enum` の列挙子が対象です。

| 型名 | 定義名 | 定義値 |
|---|---|---|
| `macro` | `SYSTEM_TICK_MS` | `10` |
| `macro` | `BUFFER_ADDR` | `(BASE_ADDRESS + REGISTER_OFFSET)` |
| `macro` | `ENABLED` | （値を持たないマクロは空欄） |
| `enum` | `STATE_RUN` | `1` |
| `(推定)` | `UNKNOWN_LIMIT` | （定義が見つからない場合は空欄） |

定義値が長い場合は末尾が省略されますが、マウスを乗せると全文が表示されます。

#### enum の列挙子

`enum` で定義された定数も定義値付きで表示されます。値が省略されている場合は、C言語の規則に従って直前の値から求めます。

```c
enum Color { RED = 1, GREEN, BLUE = 10 };   /* RED=1, GREEN=2, BLUE=10 */
enum { ANON_A, ANON_B };                    /* ANON_A=0, ANON_B=1 */
enum Tag  { T_X = 0x10, T_Y };              /* T_X=0x10, T_Y=17（10進で表示） */
enum Mode { MODE_OFF = OFFSET, MODE_ON };   /* MODE_OFF=OFFSET, MODE_ON=OFFSET + 1 */
```

- 明示された値は**記述されたまま**表示します（`0x10` は `0x10`）。計算した値は10進で表示します
- 直前の値が数値として解釈できない場合は、式に加算量を付けた形（`OFFSET + 1`）になります
- 「定義へ」ボタンで列挙子の宣言行へジャンプできます
- 同名の `#define` がある場合は、プリプロセッサが先に展開するため `#define` を優先します
- 関数内で定義された `enum` は対象外です

### 宣言のコメントの表示

宣言の**右側に書かれたコメント**を、行の右端に表示します。組込みコードでは変数の説明を宣言の右に書く習慣が多いため、その説明をそのまま一覧で確認できます。

```c
extern U8 g_warn_level;      /* 直近の警告レベル */

struct AppConfig {
    U8  mode;                /* 動作モード（0:停止 1:計測） */
    S16 offset;              // 測定値の補正量
};

#define WARN_THRESHOLD 1000  /* 警告と判定するしきい値 */
S16 hal_read_raw(U8 channel);/* ハードウェアから生値を読み出す */
```

- 対象は、グローバル変数・ローカル変数・構造体メンバ・引数・マクロ・`enum` の列挙子・呼び出し関数です。インクルードファイル内の宣言も対象です
- 行コメント（`//`）とブロックコメント（`/* */`）の双方に対応します
- **Doxygen 形式の目印も取り除きます**（`//!<` `///<` `//<` `//!` `///` `/**<` `/*!<` `/**` `/*!`）
- **同じ行にあるコメントのみ**が対象です。次の行に書かれたコメントは拾いません
- マクロ（`#define`）は、行コメント・ブロックコメントのどちらでも定義値と分けて表示します
- 長い場合は末尾を省略し、マウスを乗せると全文が表示されます

#### コメント欄の幅の調整

コメント欄の左端にある**区切り線をドラッグ**すると、幅を変えられます。

- 幅は**すべての分類にまとめて反映**されます（行ごとの調整ではありません）
- コメント欄の左端の位置は、変数・マクロ変数・関数のすべてで揃います
- 調整した幅は、別の関数を解析し直しても保持されます（パネルを閉じると既定値に戻ります）
- 型名と名前が潰れない範囲に制限されます。パネルの幅を変えたときも自動的に収め直します

> 定義値（マクロの `#define` 値）は変数名のすぐ隣に表示されます。左端を揃える対象ではありません。

### 構造体メンバの型解決

構造体・共用体のメンバにアクセスしている場合、根元の変数の型ではなく**メンバ自身の型**を表示します。

```c
struct Sub   { int member; };
struct Outer { struct Sub sub; };
struct Outer *var_ptr;

var_ptr->sub.member = 30;   // 型は struct Outer* ではなく int と表示
```

ネストしたメンバ、構造体配列の要素（`tbl[5].id`）、アロー演算子、共用体、ポインタ引数のメンバ（`data->id`）に対応しています。型は `struct Config` のようなタグ名でも、`typedef` で付けた別名でも解決できます。

`typedef` は次のいずれの書き方にも対応します（定義と `typedef` が別のファイルにある場合も解決します）。

```c
typedef struct { int a; } Direct;              /* 無名構造体を直接 typedef */
typedef struct Tag { int b; } SameLine;        /* タグ付きで同時に typedef */
struct TagC { int c; };
typedef struct TagC Separate;                  /* 定義と typedef を分離 */
typedef Separate Nested;                       /* typedef の多段重ね */
```

メンバの書き方は次のいずれにも対応します。

```c
struct Device {
#ifdef USE_EXTRA
    int   guarded;          /* プリプロセッサ条件の内側 */
#endif
    union { int a; float b; };   /* 無名共用体。a と b は Device のメンバとして扱う */
    struct { int inner; } nest;  /* 無名構造体。g.nest.inner まで辿れる */
    VOLATILE unsigned long reg;  /* 修飾子マクロ付き。型は unsigned long */
    unsigned int flag : 1;       /* ビットフィールド */
    void (*callback)(int);       /* 関数ポインタ */
};
```

「定義へ」ボタンは、構造体変数の宣言ではなく**メンバの宣言行**へジャンプします（インクルード先のヘッダも同様です）。

メンバや構造体定義が見つからない場合は、型が `(推定)` になり「定義へ」ボタンは表示されません。

> 内部変数（`struct Config local;`）と値渡しの構造体引数（`struct Config arg`）は、宣言そのものを表示する箇所のため構造体の型が表示されます。ポインタ引数はメンバへの書き込みが呼び出し元に伝わるため、メンバ単位で分類されます。

### 修飾子マクロ付きの宣言

記憶域クラスをマクロで隠す記法に対応しています。マクロ名ではなく**本来の型**を表示します。

```c
#define GLOBAL extern

GLOBAL BYTE  hoge;            /* 型は GLOBAL ではなく BYTE と表示 */
GLOBAL BYTE  buffer[16];
GLOBAL BYTE *p_data;          /* BYTE* */
GLOBAL S16   hal_read(void);  /* 呼び出し関数の戻り値型は S16 */
```

ポインタ・配列・初期化子付き・`unsigned` 付き・構造体・カンマ区切り・関数プロトタイプの各記法に対応します。関数定義（`GLOBAL void func(void)`）や関数内のローカル宣言（`LOCAL BYTE tmp;`）、インクルードファイル内の宣言も同様です。

> マクロ名は任意です。`GLOBAL` / `LOCAL` に限らず、宣言の先頭に付く同様のマクロを自動的に判別します。

### コード上のハイライト

項目名をクリックすると、エディタ上の該当箇所が一時的に強調表示され、最初の出現位置までスクロールします。配列や構造体のアクセス表現（`hoge[0]`、`hoge[i]`、`ptr->member`）にも対応しています。

### 変数名のコピー

- **個別コピー**: 各項目にマウスを乗せると表示される「コピー」ボタン
- **一括コピー**: 各分類の見出し右側にある「コピー」ボタン。分類内の項目が**改行区切り**でコピーされるため、表計算ソフトへ貼り付けると1つの変数につき1行になります

#### コピー形式の切り替え

画面上部の「コピー形式」で、コピーされる内容を切り替えられます。個別コピー・一括コピーの両方に適用されます。

| 形式 | コピーされる内容 | 表計算ソフトでの見え方 |
|---|---|---|
| **変数名** | `sensor_id` | 1列 |
| **型名 + 変数名** | `int` + タブ + `sensor_id` | 2列（A列に型名、B列に変数名） |

「型名 + 変数名」では、定義値とコメントを持つ項目に列が追加されます。

| 項目 | コピーされる内容 |
|---|---|
| コメントのみ | `U8` + タブ + `channel` + タブ + `チャンネル番号` |
| 定義値のみ | `macro` + タブ + `MAX_LIMIT` + タブ + `100` |
| 両方 | `macro` + タブ + `MAX_LIMIT` + タブ + `100` + タブ + `上限値` |
| どちらもなし | `int` + タブ + `count` |


選択した形式は、別の関数を解析し直しても保持されます（パネルを閉じると既定の「変数名」に戻ります）。

## 表示の見かた

### 配列の次元

配列の次元は、**名前と型名のどちらか一方**に表示されます。

| 状況 | 表示例 |
|---|---|
| 添字でアクセスされている | 名前 `hoge[N]` / 型 `int` |
| 添字なしで参照されている | 名前 `table` / 型 `int[8]` |
| 内部変数 | 名前 `local_arr` / 型 `int[5]` |

添字でアクセスされている場合は、コード上の値（`hoge[2]`、`hoge[i]`）ではなく**宣言された次元**（`hoge[N]`）が表示されます。そのため同じ配列への複数のアクセスは1件に集約されます。

なお**引数の配列はポインタ表記**（`int*`）になります。C言語の仕様上、引数の配列はポインタへ減衰するためです。

### マクロかどうかの判定

収集した定義に基づいて判定します。名前が大文字かどうかは、**定義が特定できなかった場合の推定にのみ**使われます。

| 状況 | 判定 |
|---|---|
| **型として定義されている** | 変数・関数のいずれにも分類しない（表示しない） |
| `#define` または `enum` の列挙子が見つかった | **マクロ**（名前の大小によらない） |
| 変数・関数の宣言が見つかった | **変数・関数**（名前の大小によらない） |
| どちらも見つからない | 大文字のみの名前ならマクロと推定（`classifyAllUppercaseAsMacros`） |

#### 型名は変数として表示しません

`#define` や `typedef` で定義した型名は、変数・関数の一覧に表示されません。

```c
#define BYTE unsigned char

a = (BYTE)(hoge + 1);   /* BYTE は型なので表示されない */
```

キャストの直後が `(` `-` `*` `&` で始まると、tree-sitter はキャストと解釈できません。`(x)(y)` は `x` が変数なら関数呼び出し、`(x)-y` は引き算として**C言語の式として正しい**ためです。収集済みの定義から型名を判別し、変数の一覧に紛れ込まないようにしています。

| 定義の書き方 | 例 |
|---|---|
| 型マクロ | `#define BYTE unsigned char` |
| マクロの連鎖 | `#define BYTE U8` + `#define U8 unsigned char` |
| ポインタ型 | `#define PBYTE unsigned char *` |
| 構造体 | `#define FOO_T struct Foo` |
| `typedef` | `typedef unsigned char BYTE;` |

値を持つマクロ（`#define MAX_LIMIT 100`）と `enum` の列挙子は値であるため、従来どおり表示されます。定義が見つからない型名は型と判断できないため表示されます。

```c
extern int GLOBAL_COUNTER;   /* 大文字でも変数として扱われる（型は int） */
void INIT_ALL(void);         /* 大文字でも関数として扱われる */
#define hoge 10              /* 小文字でもマクロとして扱われる */
```

`#define` と宣言が同名で存在する場合は、プリプロセッサが先に展開するため**マクロを優先**します。

### 推定表示

定義が見つからず型を特定できなかった項目は、変数・関数・マクロのいずれも型名欄が **`(推定)`** になります。

| 分類 | 型名欄 |
|---|---|
| 入力変数 / 出力変数 | `(推定)` |
| 呼び出し関数 | `(推定)` |
| マクロ変数 / マクロ関数 | `(推定)` |

変数か関数か、マクロかどうかは所属するセクションで分かるため、型名欄では「型が分からない」ことだけを示しています。

`(推定)` が出る主な原因は、定義位置を特定できなかったことです。次の順にご確認ください。

1. その識別子の上で **F12（定義へ移動）が効くか** — 効かなければ IntelliSense の設定側の問題です
2. `excludePaths` で意図せず除外していないか

## 設定

| 設定項目 | 既定値 | 説明 |
|---|---|---|
| `c-function-analyzer.classifyAllUppercaseAsMacros` | `true` | **定義が特定できなかった**シンボルについて、大文字のみの名前をマクロとみなします。定義が見つかったシンボルは名前によらず定義に基づいて分類されるため、本設定の影響を受けません |
| `c-function-analyzer.excludePaths` | `[]` | 定義へのジャンプ先から除外する場所（配下すべてが対象外）。ディレクトリ指定とフォルダ名指定の2通り |

### 同名ファイルが複数ある場合

ビルド時に切り替える同名ヘッダがある構成では、定義位置の候補が**複数返る**ことがあります。使用しない側を `excludePaths` で除外してください。

除外した結果、候補が1件も残らなかった場合は**定義なし**として扱います（型名は `(推定)`、「定義へ」ボタンは表示されません）。

絞り込み後も複数残る場合は、先頭を採用したうえで解析結果に注意が表示されます。

- 画面上部に注意の帯が出ます
- 該当する項目の変数名の右に **`!`** マークが付きます（マウスを乗せると説明が出ます）
- 「定義へ」ボタンで、実際に参照しているファイルを確認できます

使用しない側を `excludePaths` で除外すると、意図した定義のみが参照され、注意も表示されなくなります。

```json
{
  "c-function-analyzer.excludePaths": ["variantB"]
}
```

### excludePaths の書き方

`excludePaths` は2通りの書き方を受け付けます。どちらも**配下すべて**がジャンプ先の候補から外れます。

| 書き方 | 判定 | 例 |
|---|---|---|
| **ディレクトリ指定**<br>（`/` `\` を含む、または絶対パス） | その場所ちょうど1つ | `"legacy/old_hed"`、`"C:/SDK/deprecated"` |
| **フォルダ名指定**<br>（区切り文字を含まない） | ワークスペース内で、名前にその文字列を**含む**フォルダすべて | `"variantB"` |

同じ命名のフォルダがプロジェクト内の複数箇所に散らばっている場合は、フォルダ名指定が有効です。

```
proj/
├─ control/variantB/       →  除外
├─ control/sub/variantB/   →  除外（階層が深くても一致）
├─ hed/variantB_old/       →  除外（部分一致）
└─ hed/variantA/           →  残る
```

```json
{
  "c-function-analyzer.excludePaths": ["variantB"]
}
```

- 大文字・小文字は区別しません
- 判定対象はフォルダ名のみです。ファイル名（`variantB.h`）は除外されません
- ワークスペース外のパスは、フォルダ名指定の対象外です
- **部分一致**のため、意図しないフォルダに一致しないか確認してください（`"old"` は `goldmine` にも一致します）。ちょうど1つのフォルダだけを除外したい場合は `"./variantB"` のように区切り文字を付けてディレクトリ指定にしてください

## 制約事項

- **C/C++ 拡張への依存**: 定義位置の解決は VS Code の定義プロバイダ（F12）に委ねています。IntelliSense が動作していない環境では、型名が `(推定)` のままになります。
- **`typedef` の展開**: `typedef unsigned char BYTE;` があっても `BYTE g_flags;` は `BYTE` と表示します。
- **構造体メンバの型解決**: 構造体・共用体の定義が見つからない場合（システムヘッダ内の型など）は、メンバ自身の型ではなく根元の変数の型を表示します。
- **プリプロセッサ条件の評価**: `#if` / `#elif` / `#else` の条件は評価せず、記述されている宣言をすべて収集します。
- **マクロの展開**: マクロは展開しません。宣言の先頭に付く修飾子マクロ（`GLOBAL BYTE hoge;`）のみ、型名を正しく表示するための対応をしています。型名そのものをマクロで定義している場合（`#define U8 unsigned char` の `U8 hoge;`）は、マクロ名がそのまま型名として表示されます。

## 開発

```bash
npm install        # 依存関係のインストール
npm run compile    # ビルド（dist/extension.js を生成）
npm run watch      # 変更を監視して自動ビルド
npm test           # 型チェック + 自動テスト
npm run typecheck  # 型チェックのみ
```

テストは Node 標準の `node:test` で実装しており、追加パッケージは不要です。解析ロジックは VS Code API に依存しない構成のため、拡張機能を起動せずヘッドレスで検証できます。

解析ロジックの詳細な仕様は [docs/analysis_spec.md](docs/analysis_spec.md) を参照してください。
