# C Function Analyzer

C言語の関数にカーソルを置いて実行すると、その関数の入出力変数・内部変数・呼び出し関数の一覧を Webview 画面で可視化する VS Code 拡張機能です。

正規表現ではなく [tree-sitter](https://tree-sitter.github.io/tree-sitter/) による構文解析（AST）を用いているため、多重ポインタ・多次元配列・構造体メンバ・関数ポインタといった記述も正しく判別します。

## 使い方

1. C言語ソースコード（`.c` や `.h`）を開きます。
2. 解析したい関数の **関数名がある行（シグネチャ行）** にカーソルを置きます。
3. ショートカットキー **`Ctrl + Alt + A`** を押すか、右クリックして **「関数を解析 (Analyze C Function)」** を選択します。
4. エディタが分割され、右側に解析結果が表示されます。

> カーソルは関数の**シグネチャ行**（戻り値の型の行から引数リストの閉じ括弧の行まで）に置いてください。関数ボディの中で実行した場合は解析されません。

## 解析される内容

| 分類 | 内容 |
|---|---|
| **入力変数** | 値渡し引数、読み取りが行われているポインタ引数、読み取られているグローバル変数 |
| **出力変数** | 戻り値、書き込みが行われているポインタ引数、書き込まれているグローバル変数 |
| **内部変数** | 関数内で宣言されたローカル変数 |
| **呼び出し関数** | 関数内で直接呼び出されている関数（関数ポインタ経由の呼び出しは除外） |
| **マクロ変数 / マクロ関数** | `#define` で定義されている識別子（定義が特定できない場合は大文字のみの名前から推定） |

読み取りと書き込みの両方が行われている変数（`+=`、`++`、`*p = *p + 1` など）は、**入力と出力の両方**に表示されます。

## 主な機能

### 定義位置へのジャンプ

各項目にマウスを乗せると表示される **「定義へ」ボタン**をクリックすると、その変数・関数が宣言されている場所へ移動します。インクルードファイル内の定義であれば、そのファイルを開いて該当行へジャンプします。

定義位置を特定できない項目（`global (推定)`、標準ライブラリ関数、`戻り値 (return)` など）にはボタンを表示しません。

### インクルードファイルからの型解決

`#include "..."` を再帰的に辿り、ヘッダ内で宣言された変数・関数・マクロの情報を収集します。

```c
/* config.h */
#ifndef CONFIG_H
#define CONFIG_H
#define MAX_LIMIT 100
extern int shared_counter;
#endif
```

上記のヘッダをインクルードしていれば、`shared_counter` は `global (推定)` ではなく **`int`** と表示され、`MAX_LIMIT` は **`macro (100)`** と定義値付きで表示されます。いずれも「定義へ」でヘッダ内の該当行へジャンプできます。

### 構造体メンバの型解決

構造体・共用体のメンバにアクセスしている場合、根元の変数の型ではなく**メンバ自身の型**を表示します。

```c
struct Sub   { int member; };
struct Outer { struct Sub sub; };
struct Outer *var_ptr;

var_ptr->sub.member = 30;   // 型は struct Outer* ではなく int と表示
```

ネストしたメンバ、構造体配列の要素（`tbl[5].id`）、アロー演算子、共用体、ポインタ引数のメンバ（`data->id`）に対応しています。型は `struct Config` のようなタグ名でも、`typedef` で付けた別名でも解決できます。

### コード上のハイライト

項目名をクリックすると、エディタ上の該当箇所が一時的に強調表示され、最初の出現位置までスクロールします。配列や構造体のアクセス表現（`hoge[0]`、`hoge[i]`、`ptr->member`）にも対応しています。

### 変数名のコピー

- **個別コピー**: 各項目にマウスを乗せると表示される「コピー」ボタン
- **一括コピー**: 各分類の見出し右側にある「コピー」ボタン。分類内の項目が**改行区切り**でコピーされるため、表計算ソフトへ貼り付けると1つの変数につき1行になります

#### コピー形式の切り替え

画面上部の「コピー形式」で、コピーされる内容を切り替えられます。個別コピー・一括コピーの両方に適用されます。

| 形式 | コピーされる内容 | 表計算ソフトでの見え方 |
|---|---|---|
| **変数名** | `sensor_id` | 1列 |
| **型名 + 変数名** | `int` + タブ + `sensor_id` | 2列（A列に型名、B列に変数名） |

呼び出し関数には型がないため、「型名 + 変数名」では型名の列が空になります（列の位置は揃います）。

選択した形式は、別の関数を解析し直しても保持されます（パネルを閉じると既定の「変数名」に戻ります）。

## 表示の見かた

### 配列の次元

配列の次元は、**名前と型名のどちらか一方**に表示されます。

| 状況 | 表示例 |
|---|---|
| 添字でアクセスされている | 名前 `hoge[N]` / 型 `int` |
| 添字なしで参照されている | 名前 `table` / 型 `int[8]` |
| 内部変数 | 名前 `local_arr` / 型 `int[5]` |

添字でアクセスされている場合は、コード上の値（`hoge[2]`、`hoge[i]`）ではなく**宣言された次元**（`hoge[N]`）が表示されます。そのため同じ配列への複数のアクセスは1件に集約されます。

なお**引数の配列はポインタ表記**（`int*`）になります。C言語の仕様上、引数の配列はポインタへ減衰するためです。

### マクロかどうかの判定

収集した定義に基づいて判定します。名前が大文字かどうかは、**定義が特定できなかった場合の推定にのみ**使われます。

| 状況 | 判定 |
|---|---|
| `#define` が見つかった | **マクロ**（名前の大小によらない） |
| 変数・関数の宣言が見つかった | **変数・関数**（名前の大小によらない） |
| どちらも見つからない | 大文字のみの名前ならマクロと推定（`classifyAllUppercaseAsMacros`） |

```c
extern int GLOBAL_COUNTER;   /* 大文字でも変数として扱われる（型は int） */
void INIT_ALL(void);         /* 大文字でも関数として扱われる */
#define hoge 10              /* 小文字でもマクロとして扱われる */
```

`#define` と宣言が同名で存在する場合は、プリプロセッサが先に展開するため**マクロを優先**します。

### 推定表示

型や定義位置を特定できなかった場合は次のように表示されます。

| 表示 | 意味 |
|---|---|
| `global (推定)` | ファイル内にもインクルード先にも宣言が見つからないグローバル変数 |
| `macro (推定)` | 定義が見つからないマクロ |

## 設定

| 設定項目 | 既定値 | 説明 |
|---|---|---|
| `c-function-analyzer.classifyAllUppercaseAsMacros` | `true` | **定義が特定できなかった**シンボルについて、大文字のみの名前をマクロとみなします。定義が見つかったシンボルは名前によらず定義に基づいて分類されるため、本設定の影響を受けません |
| `c-function-analyzer.includePaths` | `[]` | `#include "..."` を解決する際に追加で探索するディレクトリ |
| `c-function-analyzer.excludePaths` | `[]` | 探索対象から除外するディレクトリ（配下すべてが対象外） |
| `c-function-analyzer.searchWorkspaceByFileName` | `true` | 探索パスで見つからない場合に、ワークスペース内をファイル名で検索します |

### includePaths の設定例

ヘッダを `include/` などにまとめている構成では、この設定が必要です。

```
proj/
├─ src/main.c        →  #include "types.h"
└─ include/types.h
```

```json
{
  "c-function-analyzer.includePaths": ["include", "common/inc"]
}
```

相対パスはワークスペースフォルダからの相対として解決され、絶対パス（`C:/SDK/include` など）はそのまま使用されます。探索順は「インクルード元ファイルのディレクトリ」→「本設定のディレクトリ（記述順）」→「ワークスペースフォルダの直下」です。

> `includePaths` は指定したディレクトリの**直下のみ**を探索します。サブディレクトリまでは降りません。

#### ファイル名検索（既定で有効）

上記の探索パスで見つからなかった場合、**ワークスペース内をファイル名で検索**します。ヘッダが多数のディレクトリに分散していても、`includePaths` を列挙せずに解決できます。

```
proj/
├─ control/6room_multi/main.c   →  #include "global.h"
├─ hed/global.h                     ← ファイル名検索で見つかる
└─ hed/6room_multi/hoge.h           ← 深い階層でも見つかる
```

| 項目 | 内容 |
|---|---|
| 有効化 | 既定で有効（`searchWorkspaceByFileName`） |
| 実行条件 | 探索パスで見つからなかった場合のみ |
| ディレクトリ付きの記述 | `#include "sub/types.h"` はそのディレクトリ構成を満たすファイルのみ対象 |
| 複数一致 | 階層の浅いものを採用し、解析結果に注意を表示 |
| 検索対象外 | `.git` などドットで始まるディレクトリ、`node_modules`、`out`、`excludePaths` に指定したディレクトリ |

検索対象の拡張子は `.h` `.hpp` `.hh` `.hxx` `.inc` `.c` `.cpp` `.cc` `.cxx` です。索引は初回利用時に作成し、ファイルの追加・削除を検知して更新します。

### 同名ファイルが複数ある場合

ビルド時に切り替える同名ヘッダがある構成では、**先に見つかった1つだけが採用されます**（優先順位は上記の探索順）。

意図と異なるファイルを参照している可能性がある場合、解析結果に注意が表示されます。

- 画面上部に注意の帯が出ます
- 該当する項目の変数名の右に **`!`** マークが付きます（マウスを乗せると説明が出ます）
- 「定義へ」ボタンで、実際に参照しているファイルを確認できます

使用しない側を `excludePaths` で除外すると、意図した定義のみが参照され、注意も表示されなくなります。

```json
{
  "c-function-analyzer.includePaths": ["variantA", "variantB"],
  "c-function-analyzer.excludePaths": ["variantB"]
}
```

`excludePaths` に指定したディレクトリは**配下すべて**が探索対象から外れます。

## 制約事項

- **インクルードの探索範囲**: `#include "..."` のみを対象とし、システムインクルード（`#include <...>`）は探索しません。ワークスペース外のヘッダは、`includePaths` に絶対パスを指定した場合のみ解決できます（ファイル名検索の対象はワークスペース内のみです）。
- **未保存の編集**: インクルードファイルは保存済みの内容を読み込みます。編集中で未保存の変更は反映されません。
- **`typedef` の展開**: `typedef unsigned char BYTE;` があっても `BYTE g_flags;` は `BYTE` と表示します。
- **構造体メンバの型解決**: 構造体・共用体の定義が見つからない場合（システムヘッダ内の型など）は、メンバ自身の型ではなく根元の変数の型を表示します。
- **プリプロセッサ条件の評価**: `#if` / `#elif` / `#else` の条件は評価せず、記述されている宣言をすべて収集します。

## 開発

```bash
npm install        # 依存関係のインストール
npm run compile    # ビルド（dist/extension.js を生成）
npm run watch      # 変更を監視して自動ビルド
npm test           # 型チェック + 自動テスト
npm run typecheck  # 型チェックのみ
```

テストは Node 標準の `node:test` で実装しており、追加パッケージは不要です。解析ロジックは VS Code API に依存しない構成のため、拡張機能を起動せずヘッドレスで検証できます。

解析ロジックの詳細な仕様は [docs/analysis_spec.md](docs/analysis_spec.md) を参照してください。
