# 使用方法

記載したコマンドのうち、`npm` のコマンド（`npm test`、`npm run compile`）は 2026-11-15 に実行して動作を確認した。
`code --install-extension` は、手元の VS Code に拡張機能をインストールするため実行しておらず「未検証」としている。画面の操作は、旧 README から移した手順で、実機では確認していない。

## 前提条件

- VS Code 1.74.0 以降。
- C/C++ 拡張（IntelliSense）。定義位置の解決に使う。F12（定義へ移動）が使えていれば条件を満たしている。

## インストール

[GitHub Releases](https://github.com/7QgvhP/c-function-analyzer/releases) から vsix をダウンロードし、次のコマンドでインストールする（未検証）。

```bash
code --install-extension c-function-analyzer-X.Y.Z.vsix
```

VS Code の拡張機能ビューの「…」→「VSIX からのインストール」でもインストールできる。

## 基本的な使い方

1. C言語ソースコード（`.c` や `.h`）を開きます。
2. 解析したい関数の **関数名がある行（シグネチャ行）** にカーソルを置きます。
3. ショートカットキー **`Ctrl + Alt + A`** を押すか、右クリックして **「関数を解析 (Analyze C Function)」** を選択します。
4. エディタが分割され、右側に解析結果が表示されます。

> カーソルは関数の**シグネチャ行**（戻り値の型の行から引数リストの閉じ括弧の行まで）に置いてください。関数ボディの中で実行した場合は解析されません。

実行中は画面右下に「関数を解析しています…」と表示され、終わると自動的に消えます。インクルードを多く辿るプロジェクトでは処理に時間がかかるため、進行中かどうかがここで分かります。

## ユースケース別の手順

### 定義へのジャンプがうまくいかない原因を調べる
画面上部の「定義の診断」ボタン、またはコマンド「定義ジャンプの診断を表示 (Show Definition Diagnostics)」で、全項目の判定結果を出力パネルに一覧表示する。判定の分類と対処の目安は [spec.md の「定義ジャンプの診断」](spec.md#定義ジャンプの診断) を参照。

### 関数の構造を図にする
解析結果画面の「フローチャートをコピー」ボタン、またはコマンド「フローチャートをコピー (Copy Flowchart as Mermaid)」でクリップボードにコピーし、GitHub・Notion・mermaid.live など Mermaid に対応した場所へ貼り付ける。

### 一覧を表計算ソフトに貼り付ける
画面上部の「コピー形式」を「型名 + 変数名 + コメント」にし、分類の見出しの右の「コピー」ボタンで一括コピーする（列の並びは [spec.md](spec.md#コピー形式の切り替え)）。

### マクロを入力変数・出力変数・呼び出し関数に含めて表示する
解析結果画面の上部の「マクロ表示」の切り替えボタンを押す（設定 `c-function-analyzer.macroDisplay` に保存される）。

### 同名のファイルが複数あるプロジェクトで使う
ビルド時に切り替える同名ヘッダがある構成では、定義位置の候補が**複数返る**ことがあります。使用しない側を `excludePaths` で除外してください。

除外した結果、候補が1件も残らなかった場合は**定義なし**として扱います（型名は `(推定)`、「定義へ」ボタンは表示されません）。

絞り込み後も複数残る場合は、先頭を採用したうえで解析結果に注意が表示されます。

- 画面上部に注意の帯が出ます
- 該当する項目の変数名の右に **`!`** マークが付きます（マウスを乗せると説明が出ます）
- 「定義へ」ボタンで、実際に参照しているファイルを確認できます

使用しない側を `excludePaths` で除外すると、意図した定義のみが参照され、注意も表示されなくなります。

```json
{
  "c-function-analyzer.excludePaths": ["variantB"]
}
```

書き方は [configuration.md](configuration.md#excludepaths-の書き方) を参照。

### サンプルで動作を確かめる
3階層のインクルードを経由した定義が解決される様子を確認できるサンプルが [samples/](../samples/) にある。`samples` フォルダを VS Code で開き、`src/sensor_main.c` の `update_sensor_status` を解析する。期待される解析結果は [samples/README.md](../samples/README.md) に書いてある。

## よくあるエラーと対処

| 症状 | 原因と対処 |
|---|---|
| 型名が `(推定)` になる | 定義位置を特定できなかった。その識別子の上で F12 が効くか（効かなければ IntelliSense の設定の問題）、`excludePaths` で意図せず除外していないかを確認する。「定義の診断」で原因を判定できる |
| 項目の名前の右に `!` が付き、画面上部に注意の帯が出る | 定義位置の候補が複数ある。使わない側を `excludePaths` で除外する |
| 型名欄に点線の下線が付く | 定義ジャンプが正常でなかった。マウスを乗せると判定結果が出る |
| ビルドは通るのに、診断で原因3・原因4が出る | IntelliSense の設定とビルドの設定がずれている。C/C++ 拡張のコマンド「C/C++: Log Diagnostics」で、実際に適用されているインクルードパスとマクロ定義を確認する。`compile_commands.json` を C/C++ 拡張に読ませると、ビルドと一致させられる |
| 「関数が定義されている場所の「関数名がある行（宣言部）」に…」と出る | カーソルを、関数のシグネチャの行（戻り値の型の行から引数リストの閉じ括弧の行まで）に置く |
| `#define FOREVER for(;;)` のようなループが図に出ない | 制御構造をマクロで隠している場合は描けない（図の先頭に注意のコメントが入る） |
